# Entries are sorted by key

Entry order is inside the commitment — the circuit hashes entries in table order — so the ordering rule is the least reversible choice in the repo: changing it re-hashes every table and costs a commitment update on every chain in both environments. Entries are sorted by `logic_ref ‖ label_ref`, making the table a function of the entry set: two branches adding tokens merge to one table, and "same entries, different commitment" is unrepresentable. Position in the table is measured to be performance-free (~35 cycles per skipped entry, beneath prover noise — see kind-table-proving-cost in the knowledge base), so nothing argues for any other order; human grouping lives in `_metadata` objects, which the generator carries through and the hash ignores.
